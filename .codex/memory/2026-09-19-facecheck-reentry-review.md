# 얼굴 → QR → 얼굴 복귀 점검 — 2026-09-19

> 아래는 수정 전 점검 당시 기록이다. 같은 날 후속 구현과 회귀 검증을 완료했으며 현재 상태는 [얼굴 확인 후 저장·모드 복귀 수정](2026-09-19-facecheck-confirmation.md)을 따른다. 아래의 미수정·미실행 표기는 당시 진단 단계에 한정한다.

- 요청: `/facecheck` 페이지 안에서 QR 모드로 전환했다가 얼굴 모드로 돌아오면 인식이 잘 안 되는 현상 점검. `main`의 `e037f8f`에서 미커밋 변경 없이 시작했다. 이번 작업은 진단과 인계 문서 기록이며 앱 소스 수정·배포는 하지 않았다.

## 확인한 원인

1. `src/app/facecheck/page.tsx`의 `switchMode`는 `busyRef`를 초기화하거나 이전 타이머를 정리하지 않는다. 얼굴/QR 체크인 요청이 대기 중일 때 얼굴 모드로 복귀하면 카메라와 안내 문구는 재시작되지만 검출 루프는 이전 `busyRef` 때문에 멈춘다. 이전 응답의 `resumeScan()`이 실행되면 다시 진행한다. 얼굴 POST와 QR 체크인 POST에는 요청 타임아웃이 없다.
2. effect의 `cancelled`는 진행 중인 `Human.detect()`를 취소하지 않는다. `loadHuman()`은 singleton을 재사용하고 `detectFaces()`에는 직렬화가 없어 복귀 후 새 추론과 기존 추론이 겹칠 수 있다. `withTimeout(5000)`도 원본 추론을 취소하지 않는다. `Human.reset()`은 설정을 기본값으로 되돌리므로 복귀 문제 해결책으로 사용하지 않는다.
- 같은 사용자에 대한 10초 억제는 의도된 기존 동작이며 위 정지/중첩과 구분한다.

## 실제 검증과 한계

- 실제 페이지 소스를 esbuild로 번들하고 React 19/Chromium에서 모델·카메라·API 경계만 mock했다. 실행한 임시 도구: `/tmp/posanmeal-face-reentry-build.cjs`, `/tmp/posanmeal-face-reentry-check.py` (임시 파일은 보존을 보장하지 않음).
- 4개 시나리오 재현: 대기 작업 없는 복귀는 정상 검출; 이전 얼굴 요청 대기 시 새 카메라 확보 후에도 600ms 동안 검출 횟수 고정 후 이전 응답 때 재개; 이전 QR 요청 대기도 동일; 이전 추론 대기 중 복귀하면 미완료 추론 2개 발생.
- 별도로 실제 `human-client.ts` wrapper와 지연 fake Human으로 동시 추론 최대 2개 및 타임아웃 후 원본 추론 존속을 확인했다.
- 실제 얼굴·실기기 인식 정확도는 미검증. 앱 코드 변경이 없어 단위 테스트·린트·타입 검사·빌드는 이번 점검에서 실행하지 않았다.

## 다음 단계
