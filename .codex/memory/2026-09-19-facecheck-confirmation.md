# 얼굴 체크인 확인 후 저장·모드 복귀 수정 — 2026-09-19

사용자가 승인한 설계를 구현했다. [이전 진단](2026-09-19-facecheck-reentry-review.md)의 busy 잔존·Human 추론 중첩 수정도 포함한다. 아래 앱 검증은 주 작업 에이전트가 실행해 보고했으며, 기록 담당자는 git diff와 관련 코드를 대조했다.

## 완료한 변경

- `/facecheck`: 학생은 학번·이름 확인/취소, 교사는 근무/개인/취소를 선택한다. 모두 10초 무응답 시 취소하며 자동 개인 체크인은 없다. 기존 Dialog의 focus trap을 사용하고 취소 버튼에 초기 포커스, 닫힌 후 모드 전환 버튼에 포커스를 둔다.
- 기존 얼굴 각도·크기·경계 geometry 검사를 재사용한다. `FaceStabilityTracker`는 동일 사용자·날짜·식사에 대해 연속 3회 유효 매칭 후 확인창을 연다. 계수 간 최소 200ms, 관측 간 최대 3초이며 대상/문맥 변경·품질 실패 때 초기화한다.
- `/api/facecheck`와 `runLocalFaceCheckIn`의 미확인 요청은 `needConfirmation`을 반환하는 읽기 전용 단계다. 명시적 확인의 `confirmation={userId,mealKind,date}`를 임베딩 재매칭 결과와 현재 날짜·식사에 대조한 뒤에만 중복·자격 검사 및 저장을 진행한다. 로컬 날짜와 식사 시간도 KST로 해석한다.
- 얼굴↔QR 전환·언마운트 시 busy·확인 대기·타이머·요청을 정리하고, AbortSignal과 세션 세대로 이전 응답이 새 모드에 반영되지 않게 한다.
- Human 로드·warmup·detect를 전역 직렬화한다. 호출자가 취소/타임아웃되어도 원본 연산 종료까지 잠금을 유지하며, 취소/만료된 대기 작업은 실행하지 않는다.
- 모델·임베딩 전처리·threshold·기존 사운드/음량은 유지했다. DB 마이그레이션·배포는 하지 않았다. 후속 사용자 요청에 따라 변경 사항을 로컬 커밋에 포함하며 원격 푸시는 하지 않는다.
