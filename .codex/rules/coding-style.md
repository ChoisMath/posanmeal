# 코딩 스타일 규칙

모든 프로젝트 공통. 가독성과 유지보수성을 최우선.

---

## 1. 주석 정책

- **기본: 주석 없음.** 잘 명명된 식별자가 무엇(WHAT)을 설명한다.
- **쓸 때:** "왜(WHY)" 가 비자명한 경우에만:
  - 숨은 제약 (외부 API 제한, 브라우저 버그 회피)
  - 미묘한 불변식 (이 순서가 중요한 이유)
  - 특정 버그 우회
  - 읽는 사람을 놀라게 할 행동
- **금지:** "이 함수는 X 를 한다" 수준의 WHAT 주석, 현재 작업/이슈 번호 언급, "Claude 가 추가함" 류 자의식 주석.

## 2. 네이밍

- 변수/함수: `camelCase`, 의도를 표현. `data`, `temp`, `foo` 금지.
- 타입/클래스/컴포넌트: `PascalCase`.
- 상수: `UPPER_SNAKE_CASE` 는 진짜 상수(환경변수 키, 고정 문자열)에만.
- 불리언: `isX`, `hasY`, `canZ`.
- 파일: 컴포넌트 `PascalCase.tsx`, 그 외 `kebab-case.ts`.

## 3. 언어

- TypeScript 우선. `any` 는 정당한 이유가 있을 때만. `unknown` + 타입 가드 권장.
- `strict: true` 기본값으로. `noUncheckedIndexedAccess` 권장.

## 4. 불필요한 추상화 금지 (YAGNI)

- 비슷한 세 줄 < 섣부른 추상화.
- 미래 가정으로 interface·base class 만들지 말 것.
- 중복이 3회 이상 실제로 나타날 때 추출.

## 5. 에러 처리

- 내부 코드와 프레임워크 보장을 **신뢰**. 방어적 if 남발 금지.
- 시스템 경계(사용자 입력, 외부 API, 파일시스템)에서만 검증.
- `try/catch` 는 실제로 처리할 수 있을 때만. 로깅 후 재throw 도 가치 있음.
- 에러 메시지는 사용자용(한국어)과 개발자용(영어/로그)을 구분.

## 6. 상수·매직 넘버

- 매직 넘버·문자열은 **의미 있는 상수**로 이름 부여.
- 단, 상수 파일을 위한 상수 파일 금지 (1회 사용되는 `const MAX = 5` 는 그 자리에).

## 7. 로그

- `console.log` 는 디버깅 중 임시용. 커밋 전 제거.
- 영속 로그는 `console.info` / `console.warn` / `console.error` 를 명시적으로 구분.

## 8. 금지 사항

- ❌ 미사용 코드 남기기 (주석 처리된 코드 블록)
- ❌ "TODO" 만 적고 이슈화 안 하기
- ❌ 타입 선언 없이 JS 코드 추가 (TS 프로젝트에서)
- ❌ 커밋 메시지에 의미 없는 "update", "fix" 단일 단어
- ❌ 한 PR 에 무관한 리팩터링 섞기
