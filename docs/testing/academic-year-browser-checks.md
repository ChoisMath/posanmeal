# 학년도 명부 화면 — 브라우저 확인 목록

360px(모바일 세로) · 768px(태블릿) · 1280px(데스크탑) 세 폭에서 모두 확인한다.
아래 목록은 구현 범위별 수동 점검 절차다. 실제 자동화 실행 결과는 마지막 절에 별도로 기록한다.

준비: 환경 파일을 읽지 않는 격리 앱 사본과 학년도 전용 테스트 DB(`127.0.0.1:55439`). 운영 DB·사진·키오스크 저장소를 연결하지 않는다. 관리자 세 종류로 각각 로그인해 본다.

- **메인 관리자**: `/admin/login`의 환경변수 계정
- **관리자 교사**: adminLevel `ADMIN`
- **서브관리자**: adminLevel `SUBADMIN`

## 1. 준비 중(PREPARING) 상태

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 1-1 | 관리자로 `/admin` → 사용자 관리 탭 | 기존 사용자 표가 그대로 보인다 |
| 1-2 | 화면 위쪽 | "학년도 기능 준비 중 — 기존 사용자 관리만 사용할 수 있습니다." 한 줄만 있다 |
| 1-3 | 화면 전체 | 오류 토스트·빈 패널·깨진 표가 없다 |
| 1-4 | 쓰기 관리자로 [추가] 클릭 | 기존 사용자 추가 창이 열리고 운영 중 명부에 추가할 수 있다 |

## 2. 학년도 선택 (Part 14a)

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 2-1 | 사용자 관리 탭 진입 | 운영 중인 학년도가 저절로 골라져 있다 |
| 2-2 | 학년도 배지 확인 | `운영 중` / `준비 중` / `지난 학년도` 중 하나가 보인다 |
| 2-3 | 다른 학년도 선택 | 배지가 바뀌고, 옆의 "현재 운영 학년도 NNNN"은 그대로다 |
| 2-4 | 360px에서 확인 | 학년도·배지·버튼이 줄바꿈되어 쌓이되, 글자가 단어 중간에서 끊기지 않는다 |
| 2-5 | 학생/교사 전환 | 열 구성이 바뀐다(학생: 학년·반·번호 / 교사: 교과명·담임·직책·권한) |
| 2-6 | 준비 중 또는 지난 학년도 선택 | [추가]가 잠긴다. 준비 중 연도에는 Excel로 추가하라는 안내가 보인다 |
| 2-7 | 학년도 목록 요청을 500으로 실패시킨다 | 오류 문구와 [다시 불러오기]가 보인다 |

## 3. 명부 표

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 3-1 | 표를 좌우로 민다 | 이름 열이 왼쪽에 고정되고 글자가 비쳐 보이지 않는다 |
| 3-2 | 표를 위아래로 민다 | 머리글이 위에 고정되고 아래 행이 비쳐 보이지 않는다 |
| 3-3 | 이름 칸을 눌러 고친 뒤 Enter | 저장되고 표가 새로 불려온다 |
| 3-4 | 같은 칸을 두 창에서 각각 고친다 | 나중 창에 "다른 관리자가 먼저 바꿨습니다" 안내가 뜨고, 값이 조용히 덮이지 않는다 |
| 3-5 | 이메일 칸 | 칸 안에서 고칠 수 없고, [이메일 변경] 버튼만 있다 |
| 3-6 | 초안 학년도의 `확인 필요` 행 | 상태 열의 사유가 잘리지 않는다. 터치로 표를 가로 스크롤하여 전체를 읽을 수 있다 |
| 3-7 | 서브관리자로 로그인 | 칸을 눌러도 편집되지 않고, [이메일 변경]·[이용 중단]이 비활성화되며 Excel 올리기·추가가 없다 |
| 3-8 | 초안에서 `제외된 항목 보기` 선택 | 제외된 사람이 표시되며 상태 열에 `명부 제외`가 보인다 |
| 3-9 | 360px에서 표의 마지막 행까지 스크롤 | 마지막 행과 표의 가로 스크롤에 접근할 수 있다 |

## 4. 계정 다이얼로그

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 4-1 | [이메일 변경] | 로그인이 끊긴다는 안내가 보이고, 360px에서 다이얼로그가 화면 안에 들어오며 내부 스크롤된다 |
| 4-2 | 잘못된 이메일 입력 | 확정 버튼이 눌리지 않는다 |
| 4-3 | [이용 중단] | "얼굴 등록이 삭제됩니다"가 보인다 |
| 4-4 | 학생의 사유 목록 | `졸업`·`전출`만 있다 |
| 4-5 | 교사의 사유 목록 | `전출`·`퇴직`만 있다 |
| 4-6 | 관리자 권한이 있는 사람을 중단 | 권한 보유 확인 체크를 해야 버튼이 열린다 |
| 4-7 | 이미 중단된 사람 | 관리자 교사에게는 [이용 재개]가 잠겨 있고, 메인 관리자에게만 열린다 |
| 4-8 | 교사 표의 권한 버튼 | 메인 관리자에게만 눌린다 |
| 4-9 | A의 이메일 변경 창에 입력 후 취소 → B의 변경 창 열기 | B의 현재 이메일로 초기화되어 A에게 입력한 값이 남지 않는다 |
| 4-10 | 학생의 이용 중단 사유를 고르고 취소 → 교사의 이용 중단 창 열기 | 사유와 관리자 권한 확인 체크가 초기화된다 |
| 4-11 | A의 권한을 선택하다 취소 → B의 권한 창 열기 | B의 현재 권한이 선택되어 있다 |

## 5. Excel 내려받기·올리기

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 5-1 | `기존 데이터 포함` 끄고 [양식 내려받기] | 빈 양식 파일을 받는다 |
| 5-2 | 켜고 다시 받기 | 현재 명부가 채워진 파일을 받는다 |
| 5-3 | 지난 학년도 선택 | `현재 학급도 함께 표시` 선택칸이 나타난다 |
| 5-4 | [Excel 올리기] → 파일 없이 | [미리보기 만들기]가 잠겨 있다 |
| 5-5 | 잘못된 파일 올리기 | 시트·행·열과 우리말 사유가 보인다 |
| 5-6 | 고쳐서 다시 올리기 | 이전 미리보기가 지워지고 새 미리보기가 만들어진다 |
| 5-7 | 미리보기 확인 | 신규/동일/변경/확인 필요/충돌과 학생·교사 건수가 보인다 |
| 5-8 | 값을 비우는 파일 | "값이 비워지는 항목"에 사람과 열이 보인다 |
| 5-9 | 신규 행이 있는 파일 | 모두 확인하기 전에는 [반영 확정]이 잠겨 있고, 잠긴 이유가 글로 보인다 |
| 5-10 | [모두 확인] | 모든 신규 행이 체크되고 버튼이 열린다 |
| 5-11 | 충돌 행 | 파일 값과 서버 값이 나란히 보인다 |
| 5-12 | [서버 값 유지] 누르기 | 즉시 저장되고(PATCH) 미리보기가 갱신된다 |
| 5-13 | 충돌 행을 하나라도 두면 | [반영 확정]이 잠겨 있다 |
| 5-14 | `전체 명부 대조`로 올리기 | 파일에 없는 사람이 **이름**으로 보인다(번호가 아니다) |
| 5-15 | 누락 확인란 | 확인하지 않으면 파일 행만 반영하고 누락은 보고만 한다는 문장이 보인다 |
| 5-16 | 중복으로 걸린 사람 | 누락 목록에 또 나오지 않는다 |
| 5-17 | 반영 범위를 바꾸기 | 미리보기·확인이 모두 지워진다 |
| 5-18 | [반영 확정] | 반영 중 표시 → 완료 문구 → 명부가 새로 불려온다 |
| 5-18a | Excel로 이름 변경 후 같은 화면에서 전체 대조를 다시 열기 | 학생·교사 누락 목록에도 변경된 이름이 표시된다 |
| 5-19 | 반영 도중 네트워크를 끊고 다시 누르기 | 두 번 반영되지 않는다(같은 요청키로 재전송된다) |
| 5-20 | 다른 창에서 먼저 반영한 뒤 확정 | 409 안내가 뜨고 "파일을 다시 올려 미리보기를 새로 만드세요"가 보인다 |
| 5-21 | 미리보기 상태에서 [취소]·창 닫기 | 서버의 미리보기 사본이 지워진다(다시 열면 처음 상태) |
| 5-22 | 360px에서 미리보기 | 다이얼로그가 화면을 넘지 않고 내부에서 스크롤된다 |
| 5-23 | 파일 A 검증 응답을 지연시킨 뒤 B로 교체 | A 응답이 B의 상태를 덮지 않으며 A의 서버 사본이 폐기된다 |
| 5-24 | 충돌 선택 저장 중 범위 변경·창 닫기·탭 이동 | 늦은 저장 응답이 새 상태를 덮지 않고 이전 사본이 최종 폐기된다 |
| 5-25 | 반영 확정을 빠르게 두 번 누르기 | 한 번만 요청하며 반영 중 파일·범위 변경을 막는다 |

## 7. 다음 학년도 준비와 전환 (14b)

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 7-1 | 쓰기 관리자로 [다음 학년도 준비] | 운영 명부를 복사할 다음 학년도를 확인하고 초안을 만든다. 운영 중 학년도는 그대로다 |
| 7-2 | 준비 중 명부에서 [학년도 전환 검토] | 학생·교사 전체 검토 결과와 신규·학급/업무 변경·이용 중단·삭제될 초안 후보 수가 보인다 |
| 7-3 | 학생·교사 누락자를 남겨 둔다 | 이름과 당시 소속을 확인할 수 있고 결정 전에는 전환할 수 없다 |
| 7-4 | 누락자의 졸업·전출·퇴직 또는 복원을 선택 | 역할에 맞는 결정만 가능하며 재검토 결과가 반영된다. 초안 항목이 없으면 복원 대신 Excel 보완을 안내한다 |
| 7-5 | 전환 경고가 있는 명부 | 미래 확정 식사일·원래 학년도 잔여 식사일·같은 학년 학생 수를 보여 주고 확인하지 않으면 전환하지 못한다 |
| 7-6 | MAIN으로 최종 확인 | 관리자 권한 유지·이용 중단자의 얼굴 등록 삭제·키오스크 업로드 완료·일시 중지 확인이 보인다 |
| 7-7 | WRITE 관리자로 같은 화면 확인 | 검토와 누락자 결정은 가능하지만 최종 전환은 할 수 없다 |
| 7-8 | 확인 중 다른 창에서 명부 변경 후 전환 | 409로 중단하고 최신 검토를 다시 읽으며 이전 경고·키오스크 확인을 초기화한다 |
| 7-9 | 전환 응답을 유실한 뒤 다시 시도 | 같은 요청키와 원래 버전으로 재전송하고 한 번만 전환한다. 성공 응답 후에만 운영 연도 표시가 바뀐다 |
| 7-10 | 360/768/1280px에서 긴 누락자 목록·확인란 조작 | 창 내부에서 끝까지 스크롤하고 모든 조작부에 접근할 수 있다 |

## 8. 지난 명부 삭제와 표시 정보 정정 (14b)

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 8-1 | 지난 학년도 선택 → [지난 명부·표시 정보] | 삭제와 표시 정보 정정이 구분되며 기본 명부 표에서는 바로 편집되지 않는다 |
| 8-2 | MAIN으로 삭제 목록 확인 | 학생·교사 전체 대상 수, 선택/전체 삭제, 사전 Excel 다운로드가 보인다 |
| 8-3 | 삭제 확인 | 명부만 삭제되고 학년도 표시 정보·식사 기록이 보존된다는 문구를 확인해야 실행된다 |
| 8-4 | 선택 삭제 또는 전체 삭제 후 월별 기록·Excel 조회 | 삭제한 명부 행은 없어지지만 당시 이름·학급과 식사 기록은 남는다 |
| 8-5 | 삭제된 사람의 표시 정보 정정 | 해당 학년도 정보만 바뀌고 삭제 명부·현재 계정·현재 학급은 복구되거나 변경되지 않는다 |
| 8-6 | READ/WRITE 관리자로 확인 | READ는 보기만, WRITE는 과거 정보 정정만 가능하며 삭제는 MAIN만 가능하다 |
| 8-7 | 같은 행을 두 창에서 정정 | 나중 요청은 409 뒤 새 값을 조회하고 자동 덮어쓰지 않는다 |
| 8-8 | 학생 목록만 로드하고 교사 조회를 지연·500 실패시킨다 | 전체 삭제 대상 확인과 최초 삭제를 할 수 없다. 양쪽 명부가 확인되어야 한다 |
| 8-9 | 실제 삭제 반영 후 응답만 차단한다 | 선택·범위·확인 해제·닫기를 막고 원래 요청키와 본문으로 결과를 다시 확인한다 |

## 9. 월별 확인 필요 목록 (14b)

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 9-1 | 합성 누락 학년도 기록이 있는 달 → [확인 필요] | 일반 학년/교사 목록에서 분류하지 못한 이력이 이름·확인 필요 문구와 함께 보인다 |
| 9-2 | 해당 기록의 체크인 셀 클릭 | 쓰기 관리자에게도 수정·삭제 요청을 보내지 않는다 |
| 9-3 | 1~2월과 3월 이동 | 기준 학년도는 3월 경계로 바뀌며 현재 학급으로 과거 소속을 대체하지 않는다 |
| 9-4 | 360px에서 탭과 표 스크롤 | 다섯 탭은 가로 스크롤되고 표 헤더·첫 열은 불투명 배경으로 고정된다 |

## 10. 체크인 검토 (14c)

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 10-1 | 급식 확인 → 체크인 검토 | 확인 대기 목록과 로컬 기록 보존 안내가 보인다 |
| 10-2 | 과거 발생·오늘 업로드한 기록 상세 | 원본 발생시각(KST), 식사일, 접수시각이 구별되고 당시 이름·소속을 표시한다 |
